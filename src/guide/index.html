EDIS Runtime Collector guide

A practical explanation of every screen, option, status, and exported file.

۱. این افزونه چه کاری می‌کند؟

EDIS Browser Runtime Evidence Collector فقط پس از اقدام صریح شما، وضعیت رندرشدهٔ همان تب را ثبت می‌کند: Viewport، هندسه، Computed Styleهای مجاز، Visibility، Overflow، روابط DOM، شواهد تعامل، شکل متن و نشانه‌های خام Elementor. افزونه صفحه را تغییر نمی‌دهد، در پس‌زمینه مانیتور دائمی ندارد، چیزی آپلود نمی‌کند و دربارهٔ خوب یا بد بودن طراحی تصمیم نمی‌گیرد.

مرز مسئولیت: WordPress دادهٔ ذخیره‌شده را می‌دهد، Browser واقعیت Runtime را می‌دهد، Python آن‌ها را Merge و تحلیل می‌کند و LLM فقط نتیجه را توضیح می‌دهد.

۲. جریان کار پیشنهادی

  1. در Options، پروفایل پوشش و گزینه‌های حریم خصوصی را تنظیم کنید.
  2. برای اتصال دقیق به دادهٔ وردپرس، فایل bridge/source-context.json را به‌صورت محلی Import کنید. این مرحله اختیاری است.
  3. در Side Panel یک Session بسازید.
  4. صفحه را در اندازه و وضعیت موردنظر قرار دهید و Capture بگیرید.
  5. برای مقایسه Responsive، اندازهٔ مرورگر را عوض کنید و Captureهای بیشتری در همان Session بگیرید.
  6. بخش Review را بررسی کنید و سپس پکیج را Validate و Export کنید.

۴. Session و Observation Set

Session چند مشاهدهٔ مرتبط را گروه‌بندی می‌کند. هر Capture یک Snapshot مستقل با ابعاد واقعی Viewport است. برچسب‌هایی مانند Desktop یا Mobile فقط نام توصیفی شما هستند؛ افزونه آن‌ها را Breakpoint رسمی Elementor فرض نمی‌کند.

Observation Set اجازه می‌دهد Python چند Snapshot از یک صفحه را کنار هم قرار دهد. تغییر DOM بین دو Capture ثبت می‌شود، اما افزونه خودش عناصر را بین Viewportها Correlate نمی‌کند.

۵. WordPress Bridge Context

پلاگین WordPress 3.2.0 فایل محدود و Schema-validated زیر را صادر می‌کند: bridge/source-context.json. آن را از Options انتخاب کنید و در صورت وجود چند سند، Document ID را مشخص کنید.

  • فایل فقط روی دستگاه شما خوانده می‌شود.
  • افزونه هیچ درخواستی به سایت وردپرس نمی‌فرستد.
  • محتوای Importشده اجرا نمی‌شود.
  • Hash، نسخه Schema و محدودیت اندازه/عمق بررسی می‌شود.
  • Capture بدون Bridge Context همچنان معتبر است، ولی Binding معمولاً ناکافی یا Unmatched است.

تأیید شما فقط Provenance است. تأیید دستی هرگز ID تکراری یا Evidence متعارض را به EXACT ارتقا نمی‌دهد.

۶. Raw Marker و Source Binding چه تفاوتی دارند؟

Raw Elementor markers
واقعیت قابل مشاهده مانند data-elementor-id، data-id و وجود کلاس‌های Elementor؛ بدون تفسیر منبع.
Source binding
تطبیق اولیه با Element Structure Index واردشده. حالت‌ها: EXACT، PROBABLE، AMBIGUOUS و UNMATCHED.
Final correlation
متعلق به Python است. Browser هیچ Correlation نهایی، Effective Value یا Resolve متغیر و Global Class تولید نمی‌کند.

۷. هویت صفحه، Widgetها و Section‌بندی

کارت «شواهد صفحه و منبع» در Side Panel صفحهٔ رندرشده را از اسناد منبع وردپرس جدا می‌کند. یک صفحه می‌تواند هم‌زمان شامل Page، Header، Footer، Popup یا Loop Template باشد. هر Runtime Node دارای Evidence Lineage است و در صورت وجود Source Context معتبر، به سند، Element و نزدیک‌ترین Section/Container منبع متصل می‌شود.

افزونه نام‌هایی مانند Hero یا Pricing را از ظاهر حدس نمی‌زند. Widget Type دقیق و Editor Label فقط از Source Context معتبر می‌آید. Label ناحیه فقط از Editor Label صریح، HTML ID مجاز، Landmark Tag/Role یا Marker فنی Elementor ثبت می‌شود.

هر Snapshot شامل runtime_regions و page_structure_summary است و پکیج فایل structure/page-structure-summary.json را نیز دارد. مدل نهایی Merged Page Graph همچنان متعلق به Python است.

۸. Capture Intent و ماژول‌ها

Capture Intent فقط هدف مشاهده را ثبت می‌کند و Rule یا امتیاز اجرا نمی‌کند.

گزینه دادهٔ خروجی
Text shape تعداد کلمات/گرافیم، Line Box، Wrap و Clipping بدون متن خام
Interaction facts Tag، Role، Tabindex، Disabled، Pointer Events و وجود Href بدون مقدار Href
Relationship graph Parent واقعی DOM، نزدیک‌ترین Parent صادرشده و Ancestorهای Position/Scroll/Clip
Color styles Computed Styleهای رنگی Allowlist شده
Screenshot فقط تصویر Viewport قابل مشاهده؛ پیش‌فرض خاموش
Text preview پیش‌نمایش کوتاه و Redacted؛ پیش‌فرض خاموش

۹. Capture Readiness

پیش از اندازه‌گیری، افزونه برای مدت محدود وضعیت Ready State، Font API، تصاویر ناقص، Animationهای فعال و تغییر ابعاد Document/Viewport را نمونه‌برداری می‌کند. این فرایند حداکثر زمان سخت دارد، DOM را تغییر نمی‌دهد، Animation را متوقف نمی‌کند و پس از Timeout نیز Capture ادامه پیدا می‌کند.

حالت‌های فرایند: STABLE، UNSTABLE، TIMEOUT، INSUFFICIENT و ERROR.

۱۲. حریم خصوصی

وقتی Include normalized URL path خاموش است، Path خام و locator_facts صادر نمی‌شوند و فقط Hash مستعار Locator باقی می‌ماند. Hash مسیر همچنان می‌تواند دادهٔ حساس مستعار باشد. وقتی Hidden Elements خاموش است، عناصر پنهان‌شده توسط Ancestor نیز حذف می‌شوند.

  • مقدار Input، Password، Hidden Input، Textarea و Select خوانده یا صادر نمی‌شود.
  • Href، Form Action، Event Handler و مقدار aria-controls صادر نمی‌شود.
  • Query String، Fragment و Credentials در Locator پیش‌فرض حذف می‌شوند.
  • Contenteditable از Text Shape و Preview کنار گذاشته می‌شود.
  • Screenshot و Text Preview پیش‌فرض خاموش‌اند و نیاز به انتخاب صریح دارند.
  • هیچ Telemetry، Analytics، Remote API یا Upload خودکاری وجود ندارد.

۱۳. وضعیت سازگاری با WordPress 7

نسخه 1.6.16 یک Fixture مصنوعی کنترل‌شده برای کلاس‌های مستندشدهٔ Visibility در WordPress 7 دارد. این Fixture فقط Pruning زیرشاخهٔ واقعاً پنهان در Viewport را آزمایش می‌کند و با برچسب verified_by_synthetic_fixture ثبت شده است. این مورد Export واقعی وردپرس یا اثبات سازگاری کامل WordPress 7+، Multisite، Elementor، Theme یا PHP نیست.

۱۵. برای خروجی بهتر

  1. در صورت نیاز به تحلیل صفحه عمومی، Logged-out یا Incognito Capture بگیرید.
  2. صفحه را به نقطه Scroll موردنظر ببرید و Popupها را آگاهانه باز یا بسته نگه دارید.
  3. برای صفحه عمیق، ابتدا Standard و در صورت Depth Limit از Deep DOM استفاده کنید.
  4. برای Responsive، چند Capture جدا در یک Session با ابعاد واقعی متفاوت بگیرید.
  5. Bridge Context همان نسخهٔ Source را Import کنید که قرار است همراه Runtime به Python داده شود.
  6. پس از Export، فایل WordPress و Browser را جداگانه به Python بدهید.

۱۶. چه نتیجه‌ای از افزونه نگیرید؟

این افزونه نمی‌گوید Padding خوب است، Touch Target کوچک است، Responsive ضعیف است یا DOM پیچیده است. اعداد و شواهد را ثبت می‌کند؛ Formulaها، Policyها، Final Correlation و UX Finding فقط در Python اجرا می‌شوند.

1. What the extension does

EDIS Browser Runtime Evidence Collector records the rendered state of the active tab only after an explicit user action. It captures viewport facts, geometry, allowlisted computed styles, visibility, overflow, DOM relationships, interaction facts, privacy-safe text shape, readiness observations, and raw Elementor markers. It does not modify the page, monitor it persistently, upload data, score UX, or generate fixes.

Boundary: WordPress supplies saved source evidence, Browser supplies runtime observations, Python verifies/merges/analyzes them, and the LLM explains the Python result.

2. Recommended workflow

  1. Choose coverage and privacy options.
  2. Optionally import bridge/source-context.json from WordPress 3.2.0.
  3. Create a session in the side panel.
  4. Capture the page at the required viewport and state.
  5. Add more observations to the same session for responsive comparison.
  6. Review completeness and diagnostics, then validate and export.

4. Sessions and observation sets

A session groups independent snapshots of one review task. Labels such as Desktop or Mobile are descriptive only; measured viewport dimensions are authoritative. The extension never infers official Elementor breakpoint names from width.

5. WordPress Bridge Context

Import the bounded, schema-validated bridge/source-context.json artifact to enable preliminary source binding. Parsing is local, imported content is never executed, no WordPress request is made, and capture without context remains valid.

User confirmation is provenance only and cannot upgrade duplicate or conflicting evidence to EXACT.

6. Raw markers, binding, and final correlation

Raw markers
Observed data-elementor-id, data-id, and Elementor class facts.
Source binding
Preliminary EXACT, PROBABLE, AMBIGUOUS, or UNMATCHED evidence against the imported source index.
Final correlation
Python-owned. The extension does not resolve source values, variables, classes, or responsive inheritance.

7. Page identity, widgets, and sections

The Page and source evidence card separates the rendered page from imported WordPress source documents. One rendered page may contain the page document, header, footer, popup, or loop templates. Each runtime node has evidence lineage and, when validated source evidence is available, may reference its source document, element, and nearest source section or container.

The extension never guesses labels such as Hero or Pricing from visual appearance. Exact widget types and editor labels come only from validated Source Context. Region labels are limited to explicit editor labels, privacy-permitted HTML IDs, landmark tags/roles, or technical Elementor structure markers.

Snapshots contain runtime_regions and page_structure_summary; the package also contains structure/page-structure-summary.json. Python owns the merged page graph and final correlation.

8. Evidence modules

  • Text shape: counts, wrapping, line boxes, and clipping without raw text.
  • Interaction facts: tag, role, tabindex, disabled state, pointer events, and presence flags.
  • Relationship graph: real DOM parent plus nearest emitted, positioned, scrolling, and clipping ancestors.
  • Capture readiness: bounded observations of document, fonts, images, animations, and layout stability.
  • Screenshot/text preview: separate explicit opt-ins, disabled by default.

11. Privacy rules

When raw path inclusion is disabled, the raw path and locator facts are withheld and only a pseudonymous locator hash remains. Hashed paths can still be privacy-sensitive. With hidden-element collection disabled, descendants hidden by an ancestor are excluded.

  • Input, password, hidden-input, textarea, and select values are not exported.
  • Href values, form actions, event handlers, and aria-controls values are not exported.
  • Queries, fragments, and credentials are excluded from default locator evidence.
  • Contenteditable content is excluded from text shape and preview.
  • No telemetry, analytics, remote API, automatic upload, cookie, or history access exists.

12. WordPress 7 compatibility status

Version 1.6.16 includes a controlled synthetic fixture for the documented WordPress 7 viewport-visibility classes. It verifies hidden-subtree pruning only and is labeled verified_by_synthetic_fixture. It is not a real WordPress export or proof of complete WordPress 7+, Multisite, Elementor, theme, or PHP compatibility.

14. What the extension does not conclude

It does not decide whether spacing, responsive behavior, typography, touch targets, DOM depth, or grouping are good or bad. It records evidence; versioned Python rules and formulas produce findings later.

حداقل خوراک پایتون در نسخه 1.6.16

Source Context همان صفحه را وارد و سند را انتخاب کنید؛ سپس Desktop، Tablet و Mobile را با سه عرض واقعی متمایز در یک Session ثبت کنید. برچسب پروفایل فقط Provenance است و Breakpoint واقعی را تعیین نمی‌کند. اگر Feed آماده نباشد، Blockerها حفظ می‌شوند و می‌توانید همان واقعیت‌های ثبت‌شده را به‌صورت Runtime Evidence صادر کنید.

Minimum Python Feed in 1.6.16

Import and confirm the matching Source Context, then capture Desktop, Tablet, and Mobile at three distinct measured widths in one session. Requested profiles are provenance labels, not resolved breakpoints. If the feed is not ready, blockers remain in force and the same recorded facts may be exported as ordinary Runtime Evidence.

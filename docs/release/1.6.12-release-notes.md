Version 1.6.12 fixes the verified export-blocking defects found after 1.6.11. It preserves the strict Minimum Python Feed readiness policy while restoring the documented availability of ordinary Runtime Evidence for incomplete sessions.

## Implemented

- Centralized one-way export compatibility: a `MINIMUM_PYTHON_FEED` session may produce `RUNTIME_EVIDENCE`, but a `RUNTIME_EVIDENCE` session may not produce a Minimum Python Feed.
- Preserved every Minimum Python Feed readiness blocker and all deterministic evidence facts.
- Added a runtime-evidence fallback action only when ordinary runtime export has no independent blockers.
- Split preflight rendering into blocking requirements and non-blocking coverage warnings.
- Made Runtime Evidence the default workflow for new sessions.
- Added policy, preflight, package-builder, and real dialog/download regressions.

## Contract and compatibility

No evidence schema, package path, permission, canonicalization profile, checksum algorithm, capture fact, or Python-owned computation boundary changed. A runtime package created from a Minimum session retains the factual `workflow_mode` recorded in the Capture Session artifact; the export does not rewrite or upgrade evidence.

## Migration

No database migration is required. Existing 1.6.11 sessions remain readable. Existing incomplete Minimum Python Feed sessions can be exported as Runtime Evidence after installing 1.6.12, provided the session has at least one observation and is not capturing or failed.

## Remaining limitation

Minimum Python Feed remains unavailable until all readiness requirements are satisfied. The fallback deliberately does not embed Source Context or claim feed readiness.

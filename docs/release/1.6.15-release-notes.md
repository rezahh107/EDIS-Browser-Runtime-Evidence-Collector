## هدف

این نسخه شکاف‌های باقی‌ماندهٔ Release Qualification نسخهٔ 1.6.14 را بدون تغییر قراردادهای شواهد برطرف می‌کند: زنجیرهٔ Evidence مرورگر fail-closed شده، Canonical JSON در برابر cycle و ورودی‌های بیش‌ازحد عمیق/بزرگ رفتار دترمینیستیک دارد، و Chunkهای legacy فاقد hash دیگر به‌صورت خاموش پذیرفته نمی‌شوند.

## اصلاحات

- Aggregator دیگر هیچ مسیر اجرایی مرورگر را hard-code نمی‌کند.
- هر نتیجهٔ `PASS` مرورگر باید به executable، SHA-256 آن، family/version واقعی، Build hash، Manifest hash، Extension ID، Service Worker URL، OS و گزارش Playwright متصل باشد.
- سه Scope مستقل تعریف شده است: `AUTOMATED_PLAYWRIGHT_CHROMIUM`، `EXACT_GOOGLE_CHROME` و `EXACT_MICROSOFT_EDGE`.
- `PASS` با Browser ناشناخته یا provenance ناقص ممنوع است.
- Canonicalization با `WeakSet` چرخه را تشخیص می‌دهد و سقف‌های نسخه‌بندی‌شدهٔ depth/node/collection را اعمال می‌کند.
- خطاهای Canonicalization از نوع `TypeError` با code ثابت هستند و دادهٔ ناسالم به sentinel تبدیل نمی‌شود.
- `putChunk` از این نسخه همیشه SHA-256 واقعی می‌نویسد.
- Chunk legacy فاقد hash فقط با checksum کامل Snapshot پذیرفته می‌شود و Diagnostic عملیاتی ثبت می‌کند؛ Recovery بدون checksum کامل fail-closed است.
- تست مهاجرت IndexedDB v3→v4 حفظ داده و ایجاد indexهای `screenshots.sessionId` و `jobs.status` را اثبات می‌کند.
- تست‌های موجود Service Worker termination/recovery همان تست‌های هنجاری باقی مانده‌اند.

## سازگاری

هیچ Schema شواهد، Permission، Package path، Network behavior یا مرز مالکیت WordPress/Browser/Python تغییر نکرده است.

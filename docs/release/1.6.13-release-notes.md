# EDIS Runtime Collector 1.6.13 — Export Provenance and CI Hardening

```yaml
extension_version: 1.6.13
release_date: 2026-06-24
implementation_status: implemented
architecture_status: preserved
runtime_snapshot_schema: 1.6.0
capture_session_schema: 1.1.0
python_feed_readiness_schema: 1.1.0
runtime_package_manifest_schema: 1.4.1
```

نسخهٔ 1.6.13 سیاست Export نسخهٔ 1.6.12 را fail-closed می‌کند و پوشش CI مسیر بحرانی Export fallback را افزایش می‌دهد. این نسخه رفتارهای Runtime و شواهد ثبت‌شده را تغییر نمی‌دهد و فقط منشأ Workflow، مجازبودن Purpose و Gateهای اعتبارسنجی را سخت‌تر می‌کند.

## تغییرات پیاده‌سازی‌شده

- Session با `workflow_mode: null` فقط می‌تواند Runtime Evidence صادر کند؛ حتی اگر Readiness خوراک Python کامل باشد.
- Session قدیمی دارای Capture و `workflow_mode: null` در Captureهای بعدی Runtime-only تلقی می‌شود و UI اجازهٔ تبدیل آن به Minimum Feed را نمی‌دهد.
- Runtime fallback فقط وقتی نمایش داده می‌شود که Session صریحاً `MINIMUM_PYTHON_FEED` بوده، Purpose درخواستی Minimum باشد و Runtime export مانع مستقل نداشته باشد.
- Smoke test مرورگری Export fallback در Push و Pull Request اجرا می‌شود؛ Suite کامل مرورگر همچنان طبق Schedule هفتگی و Release workflow اجرا می‌شود.
- Runner مرورگر از `--test-file` و `--grep` برای اجرای هدفمند پشتیبانی می‌کند، اما همچنان Build، executable resolution و unpacked-extension preflight را اجرا می‌کند.
- عبارت اشتباه مربوط به Performance release در README اصلاح شد: Performance hardening متعلق به 1.6.11 است.
- وابستگی انتقالی توسعهٔ `undici` به 7.28.0 ارتقا یافت و Audit کامل به صفر Vulnerability رسید.

## قرارداد و سازگاری

هیچ Evidence Schema، Package Path، Permission، Canonicalization Profile، Hash Algorithm، Capture Fact یا مرز مالکیت Browser/Python تغییر نکرده است. Sessionهای قدیمی قابل خواندن باقی می‌مانند؛ فقط مجازبودن Minimum Feed برای Sessionهای فاقد Workflow Provenance محدودتر شده است.

## مهاجرت

Migration دیتابیس لازم نیست. Session قدیمی با `workflow_mode: null` و Capture موجود به‌صورت امن Runtime-only باقی می‌ماند. برای تولید Minimum Python Feed باید Session جدیدی با Workflow صریح Minimum ساخته و تمام Captureها تحت Guard همان Workflow ثبت شوند.

## محدودیت باقی‌مانده

اجرای واقعی Smoke E2E در محیطی که Load Unpacked و Service Worker افزونه را پشتیبانی کند همچنان Gate ضروری است. کد و CI آن موجود است، اما نتیجهٔ Runtime محلی باید جداگانه ثبت شود.

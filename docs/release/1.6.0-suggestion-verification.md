# Browser 1.6.0 Suggestion Verification

## Scope

The 1.5.0 source and complete packages were compared with the 1.6.0 implementation. Claims below are based on source inspection and executed deterministic tests unless explicitly marked otherwise.

| Suggestion | Verification | 1.6.0 status | Evidence |
|---|---|---|---|
| Prune effectively hidden descendant subtrees | Confirmed defect in 1.5.0 walker | Implemented | `selectElements.ts`; hidden-depth regression tests |
| Record hidden pruning transparently | Required to explain omitted evidence | Implemented with subtree count and direct-child lower bound | snapshot/session schemas and side-panel summary |
| Wait for visible incomplete images within readiness budget | Confirmed early-stability defect | Implemented | `captureReadiness.ts`; offscreen, visible and hidden-ancestor tests |
| Separate total and in-viewport incomplete images | Confirmed ambiguity | Implemented | Runtime Snapshot 1.4.0 |
| Separate discovered/traversed and emitted metrics | Confirmed scope ambiguity | Implemented | `document_metrics` and schemas |
| Rename lineage `observation_id` | Confirmed it duplicated `snapshot_id` | Implemented as `snapshot_id` | model, schema and canonical ordering |
| Strict schema index | Confirmed 1.5.0 schema was too permissive | Implemented | closed `schema-index.schema.json` |
| Remove duplicated diagnostics storage | Confirmed duplicate payload/envelope storage | Implemented | envelope array constrained empty; regression test |
| Manifest-derived version badge | Confirmed useful operational check | Implemented | popup and side panel use `chrome.runtime.getManifest().version` |
| Runtime instance model | Architecturally valid if factual and conservative | Implemented | direct/ancestor source-marker grouping; no final meaning inference |
| Source/runtime cardinality | Architecturally valid as candidate evidence | Implemented | snapshot field and dedicated coverage artifact |
| Document instance boundaries | Architecturally valid with source and relationship evidence | Implemented | deterministic disconnected-root grouping |
| Capture state/environment warnings | Architecturally valid factual evidence | Implemented | focus, scroll, iframe, modal, admin bar, editor, animation and image facts |

| Computed-style origin availability | Safe when it does not claim origin | Implemented as availability only | `RESOLVED_COMPUTED_VALUE_ONLY`; CSSOM inspection false |
| Registry fingerprints | Useful phase-two proposal | Not implemented | requires a versioned WordPress Bridge Context contract change |
| Source-driven responsive capture plan | Useful phase-two proposal | Not implemented | requires imported breakpoint registry evidence and UI/workflow contract |
| Full CSSOM rule-origin analysis | High complexity and cross-origin limitations | Not implemented | remains proposed/unverified |

## Important interpretation rule

A repeated source element key is not automatically a Loop Template. Browser emits `REPEATED_TEMPLATE` only when validated source context identifies the source document as `loop-item`; otherwise it emits `MULTIPLE_RUNTIME_ROOTS`. Python remains responsible for final correlation and any semantic interpretation.

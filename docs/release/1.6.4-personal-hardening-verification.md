## Why this release exists

Version 1.6.4 fixes three confirmed persistence races from the WOLF DEBUGGER audit of 1.6.3:

1. same-tab concurrent `CAPTURE_START` could create two active jobs;
2. same-session multi-tab starts could reserve duplicate `observationIndex` values;
3. concurrent finalization could persist both snapshots while losing one session capture summary.

It also removes Python bytecode cache artifacts from the source package path.

## Implemented changes

### Atomic capture start

`EvidenceRepository.beginCapture()` now reloads the stored session and checks active jobs by tab and by session inside the same IndexedDB transaction that writes the new job. A second active capture for the same tab or same session is rejected deterministically.

### Observation-index reservation guard

The stored session capture count must match `job.config.observationIndex` at write time. If another capture has already reserved or completed the next index, the new start fails before corrupting session state.

### Transactional finalization merge

`commitCapture()` now reloads the current session in the final commit transaction, extracts the capture summary for the committed snapshot, merges it with existing summaries by `snapshot_id`, and sorts deterministically by `captured_at` then `snapshot_id`.

### Source package hygiene

`generate-source-manifest.mjs`, `package-release.mjs`, and `package-personal-release.mjs` now exclude or reject `__pycache__` and `*.pyc` paths. Existing cache artifacts were removed from the source tree.
